Result

The merchant site handled every SATIM response correctly. It confirmed each payment with SATIM from the server, and it showed each result to the customer as SATIM returned it. Four test cards did not produce the result their scenario name describes. Those four outcomes come from SATIM's test data, and we ask SATIM to review them below.

Points for SATIM

We ask SATIM to confirm the expected result, or provide replacement test cards, for the following:

  1. Card limit exceeded and terminal / transaction amount limit exceeded were approved at 1 200,00 DZD and at 2 376 000,00 DZD. Which amount or setting should produce the refusal?
  2. Expired card (expiry 12/2022) was approved. Is this card still valid for the scenario?
  3. Card no longer exists on issuer server (expiry 01/2025) cannot be entered because 2025 is not in the payment page's year list. Is a replacement card available?
  4. Some refusals (error 2003) and the cancellation arrive with English text only, which then appears on French and Arabic pages. Is a translated message available?

Technical observations

  • All calls use POST with form encoding; SATIM accepted this for registration, confirmation and refund.
  • Confirmation (acknowledgeTransaction.do) returned identical answers when called twice for the same order, paid or unpaid.
  • An unknown order number is answered with HTTP 401 and the text "Transaction is not found", instead of the documented error code 6. The module handles both.
  • After any refund SATIM reports order status 4; the remaining captured amount tells a partial refund from a full one. The module shows these as "partially refunded" and "refunded".
  • The hosted payment session lasts about ten minutes. Payments completed but not returned to the site are confirmed later by a reconciliation job.
